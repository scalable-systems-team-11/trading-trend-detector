Decision: workers must equal partitions. With one worker over 4 partitions a 300k-event sample lost 1,003 windows and changed 9,997 (the single watermark jumps ahead of lagging partitions and their events count as late); with one partition per worker the output was identical to the single-process reference. Verified only against a stub broker and fakes: not yet run against a real Kafka, and no throughput results yet. `bench/compare_outputs.py` checks Kafka vs TCP output.

- 20.10 (Klaus, AI-assisted) Added a PyFlink job (compose profile `flink`, `flink/job.py`, `flink/logic.py`) next to the Kafka workers, reading the same topic. Decision: Flink's per-partition watermarks (minimum over partitions) replace the "one worker per partition" rule, and window closing uses keyed state plus event-time timers. To avoid a second copy of the validation and EMA code, `receiver/processor.py` was refactored into `StreamProcessor.parse`, `advance_ema` and `window_row` (behaviour unchanged, existing tests pass). Findings: PyFlink 1.20 needs Python 3.11 and has no aarch64 wheels (built from source in the image). Output equals the TCP receiver's on a 300k-event slice (0 missing, 0 different); on the full day it has the same 296,216 rows but 2,617 differ in 47 symbols, all because TCP's global watermark dropped 68 events as late and Flink dropped none. Speed: ~21k events/s on the full day (550 s, 4 partitions, consumer only), i.e. no faster than the producer-bound Kafka workers (27k) and far below the processor alone (~600k): PyFlink pays several JVM/Python crossings per record. PyFlink's default local "loopback" mode ran everything in one Python process (6-8k events/s); `_python_worker_execution_mode=process` gave ~3.5x. Larger state cache: no effect; thread mode: GIL-bound, >7x slower. Earlier benchmark note: the two TCP records in `output/benchmarks.jsonl` ran at 360x replay speed, so their 145 s is pacing, not capacity, and the second one is mislabeled `kafka-4w`; the 79k ev/s TCP figure and the 27k ev/s Kafka figure are not comparable. The full-day Kafka output differs from TCP in 1,166 rows of 20 symbols (TCP's global watermark dropped 68 events as late, the workers 48), plus 19 final-window rows missing.
